Gmail Organizer

  • Python
  • Gmail API
  • OAuth 2.0
  • Automação

Automação de linha de comando — sem interface, só back-end

O problema
Caixa de entrada com vaga, nota fiscal e aviso de banco tudo misturado, e a triagem sempre sobrando para depois. O script faz essa separação a cada execução, sem eu abrir o Gmail.
Como classifica
Cada label tem um conjunto de termos — CURRICULO, COMPRAS e BANCOS. O corpo do e-mail é pontuado contra todos eles, uma ocorrência vale um ponto, e a maior pontuação leva. Empate fica com a primeira; pontuação zero não move o e-mail.
Arquitetura
Quatro camadas com uma responsabilidade cada: o main.py só instancia e injeta as dependências, o service orquestra o fluxo, o classificador decide a label e o repositório conversa com a API. O service não sabe que existe um Gmail do outro lado — trocar a fonte dos e-mails não encosta na regra.
Autenticação
OAuth 2.0 no escopo gmail.modify. O token fica em disco e só o fluxo de consentimento roda na primeira vez; nas seguintes ele só se renova. Nem credentials.json nem o token vão para o repositório.
Tratamento de erros
Toda falha de rede da API vira uma ConexaoError com mensagem própria, em vez de vazar o HttpError cru do Google — o erro passa a dizer o que fazer, não só o que quebrou.
Uma nota sobre as imagens
O projeto não tem interface: as peças ao lado são diagramas do funcionamento e a saída real que o script imprime no terminal.
